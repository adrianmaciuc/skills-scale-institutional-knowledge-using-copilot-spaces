# OctoAcme Project Management Documentation

Welcome to the OctoAcme project management documentation set. This folder is the entry point for the shared guidance, standards, and templates our teams use to deliver projects with clarity, alignment, and accountability.

## Overview

OctoAcme uses a practical, customer-first project management approach that balances business value, team capacity, and quality. Our process is built on clear ownership, iterative delivery, and measurable outcomes so teams can move quickly without losing visibility or control.

### Core principles
- Customer-first: prioritize customer value and usability.
- Iterative delivery: break work into small, testable increments.
- Clear ownership: every project has explicit PM and product leadership coverage.
- Data-informed decisions: measure impact and iterate based on evidence.
- Psychological safety: encourage learning, feedback, and transparent communication.

## Project lifecycle

OctoAcme projects typically move through five stages:

1. Initiation
   - Validate the problem, stakeholders, success metrics, and whether the initiative is worth pursuing.
2. Planning
   - Define scope, milestones, backlog priorities, dependencies, and delivery responsibilities.
3. Execution and Tracking
   - Deliver value in small increments while monitoring progress, quality, and blockers.
4. Release and Deployment
   - Validate readiness, deploy with appropriate controls, and confirm the impact.
5. Close and Retrospective
   - Capture what went well, what can improve, and what to carry forward.

## Core roles

- Project Manager (PM): coordinates schedules, risks, communications, and execution health.
- Product Manager (PdM): defines the problem, priorities, and success criteria.
- Developers: implement work, own quality, and collaborate on design and trade-offs.
- QA / Testing: validate acceptance criteria and release readiness.
- Stakeholders: provide input, sponsorship, and key decisions.
